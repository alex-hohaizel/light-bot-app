# Світло · Відновлення і розвиток 1.0.0

Веди один чинний продукт як відповідальний інтегратор. Працюй українською. Зберігай користувацький намір і доводь доручений етап до перевірного результату. Підтримуй мінімум старих Києва, Вінниці, Одеси й Харкова, додатковий фактичний legacy-обсяг і всі території з підтвердженими даними. Доступ до основного та резервного API коштує 0. Зберігай ідентичність чинного бота, домен і профілі за чинним рішенням власника. Перевіряй конкретний об’єкт, права й дозволений scope перед дією.

## Почати або відновити

1. Знайди фактичні project instructions, прийнятий паспорт, вимоги, поточну контрольну точку, рішення, дозволи та джерельні ревізії. Особисті та швидкозмінні дані тримай у проєкті. Використай відомий точний шлях або перевірений віддалений ID. Назва папки сама не доводить ідентичність.
2. Прочитай [спільний маршрут Work ↔ Codex](references/joint-work-codex.md) на початку нового чи відновленого етапу, за браку передумови та при передачі. Спочатку перевір придатність поточного середовища. Один придатний дозволений маршрут виконуй самостійно. Для ручного кроку підготуй точні входи, команду або UI-дію, критерій успіху й повернення.
3. Прямі БРИФ і ВІДНОВИ веди за [протоколом](references/briefing-protocol.md). Чинні погодження незмінного scope успадковуй. У локальному виправленні уточнюй лише матеріальну прогалину. Застосовуй [протокол взаємодії](references/interaction-protocol.md) і [сумісність інструментів](references/tool-compatibility.md).
4. Перевір відповідність актуального SHA, input hashes і scope. Звір нез’ясований результат старої зовнішньої дії до повтору. Pause зберігається до застосовного resume. Якщо бракує capability, дай точний blocker, продовжуй незалежні дозволені кроки.
5. Відділи дозвіл на створення агента від доручення виконувати продукт та конкретних зовнішніх дій. Власницький доступ, можливість хоста і право на дію перевіряй окремо. Уже наданий точний дозвіл застосовуй без повторної згоди.

## Розподілити роботу

Використай [карту вимог і маршрутів](references/workflow.md). Одна задача містить assigned requirement IDs, exact inputs/hashes, owner, owned paths, outputs/consumer, scope, ресурси, acceptance, stop і return. Паралельні виконавці мають окремі артефакти. Признач одного writer для shared API, БД, registry, інтеграції та cutover. Для критичних змін потрібен незалежний reviewer без авторства цієї частини.

Перед новим engine, модулем чи reusable skill застосуй [discovery спеціалістів](references/specialist-discovery.md). Знайди актуальну придатну навичку за stable name, прочитай джерело, зафіксуй version/hash і рішення reuse/compose/extend/create_gap. Спочатку використай достатній наявний connector/API/CLI. Після переходу між Work і Codex перевір фактичну доступність повторно.

- Веб, UX і Mini App передавай `@app-atelier-director` у Work або `$app-atelier-director` у Codex.
- Telegram, діалог, платформи й доставка — `@chatbot-atelier-director` або `$chatbot-atelier-director`.
- Виготовлення додаткової reusable skill — актуальному `design-specialist-skills` за предметним gap і чинним scope.

Для App і ChatBot виконай [контракт компонентів](references/specialist-orchestration.md). Збережи єдині parent intent, права та IDs identity/address/schedule/event. Підготуй окремий JSON handoff за `assets/component-handoff.template.json`, вкажи одного owner спільного контракту, запусти `python3 -B scripts/check_component_handoff.py HANDOFF.json --root PROJECT --ready`. Передачу, отримання, запуск і приймання фіксуй окремо. Зовнішня навичка є залежністю, її вміст і встановлення одержувач перевіряє.

Сирий production-експорт потребує визначеного scope. |

| P2 | Спільні контракти та ризиковий зріз адреса→зміна→тестовий Telegram→веб/Mini App. | Одна ревізія даних, точний текст/картка, негативний сценарій повтору й відмови. |
| P3 | App/ChatBot handoff, адаптери й інтеграція за прийнятими контрактами. | Відтворювана збірка, isolated тестові конфігурація й дані, контрактні перевірки. |
| P4 | [Репетиція міграції](references/migration-delivery.md) й незалежне QA на staging. | Звірка кожного акаунта, повтор імпорту, відновлення та rollback, приватність і цільові пристрої. |
| P5 | [Операції](references/operations.md), точний реліз і дозволена кампанія оновлення. | Чинні права, один sender, контрольна вибірка, квитанції, критерії зупинки й повернення нових записів. |
| P6 | Freshness/джерела, інцидент, нові ОСР, регресії й checkpoint. | Докази для зачепленого scope, незалежні гілки збережені, exact next action. |

Звичайні оборотні дії в дорученому scope виконуй до завершення. Матеріальний відступ від прийнятого наміру відкриває лише зачеплені рішення й докази. Два однакові невдалі ремонти змінюють діагностику.

## Перевірити й закрити

Використовуй [контракт створеного агента](references/generated-agent-contract.md), [спільне ядро](references/cross-domain-core.md), [предметну модель](references/domain-model-2.md), [виробничі рецепти](references/production-recipes-2.md) та [контракт доказів](references/depth-evaluation-2.md). Конкретні LBA правила в domain/migration/operations/workflow спеціалізують ці зобов’язання.

Для кожного due must замкни requirement→rule/contract→operation/recipe→attempt→output→consumer→evidence. Фіксуй actual actor, input/output hashes, спосіб, середовище, результат і межі. Код, structural check, інтеграція, пристрій, owner acceptance та спостережений production мають власні докази. Регресійний тест має виявляти заявлений дефект.

Для локального реєстру й checkpoint прочитай `python3 -B scripts/lba_audit.py --help` і [формат допоміжних записів](references/workflow.md). Helper читає дані й перевіряє заявлені поля. Фактичну дату, права, походження, результати ОСР і цільовий runtime підтверджуй окремими спостереженнями. Числа й статуси у файлі не створюють authority.

Зберігай source/intent/decisions, dependency graph, lexically searchable knowledge, evidence, jobs/unknown effects і readable checkpoint у проєкті. Vector RAG або новий сервер додавай за виміряною потребою. Завершення етапу містить exact scope, requirement verdicts, артефакти/hashes, gaps, чинні рішення, дозволи, наступну дію/stop/return. Надай короткий результат і потрібний наступний крок українською.
