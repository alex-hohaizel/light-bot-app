# Локальна тестова копія LIGHT BOT APP

Копія використовує власну синтетичну БД та вигадані профілі. Окремий огляд даних показує реальні збережені публічні відповіді без адресної сертифікації. Чинний Replit, webhook, Telegram і виробнича БД не підключені. Жовта смуга позначає локальне середовище. Основа дизайну та мовна політика погоджені власником; повне приймання продукту, даних і пристроїв лишається окремим.

## Відкрити зараз

[Новий застосунок](http://127.0.0.1:5417/review) · [Бот](http://127.0.0.1:5417/review/bot) · [Зафіксовані дані чотирьох міст](http://127.0.0.1:5417/review/data). Поточний запуск створений у цій Codex-сесії. Старий інтерфейс збережений на `/` як технічне джерело legacy-сценаріїв.

## Повторно запустити на Mac

Потрібен Node 24; під час перевірки використано Node 24.22.2. Відкрийте Terminal і виконайте:

```sh
cd "/Users/admin/Projects/LIGHT BOT APP [CODEX]/app"
npm start
```

Після повідомлення `serving on port 5417` відкрийте `http://127.0.0.1:5417/review`. **Ctrl+C** завершує власні процеси застосунку та БД. Якщо поточна копія вже працює, відкрийте її за посиланням; другий запуск відхилить зайнятий порт.

Кожен новий запуск створює свіжу PostgreSQL 16 у `.local/light-bot-app/synthetic-db-*`, тільки на `127.0.0.1:55432`, без Unix socket і системної служби. У ній з'являються synthetic marker, схема, один вигаданий користувач та тестова адреса. Після штатної зупинки ця створена для запуску БД видаляється. App і Bot використовують один тестовий профіль. Зміни зберігаються між запитами та оновленням сторінки у поточному запуску; це не сховище виробничих профілів. На екрані бота можна явно обрати новий або готовий тестовий профіль. Окремо перевірено перезапуск Node зі збереженою тестовою базою.

Після змін коду:

```sh
npm run check
npm run test:backend
npm run build
npm start
```

`npm run dev` також збирає і запускає цю саму ізольовану копію. Вхідні параметри БД та credential-поля не потрібно вводити: launcher використовує фіксовані тестові значення й передає дочірнім процесам лише перелік дозволених змінних.

## Встановлення на чистій копії

З кореня цього репозиторію:

```sh
npm ci --prefix app --ignore-scripts --no-audit --no-fund
npm ci --prefix tools/local-runtime --ignore-scripts --omit=optional --no-audit --no-fund
cd app
npm run build
npm start
```

Runtime-пакет містить переносні PostgreSQL binaries для цього Darwin arm64 host. Він не створює користувача ОС або фонову системну службу. Інший host потребує окремої перевірки платформи. Автоматичні install lifecycle-скрипти вимкнено; необхідні symlinks PostgreSQL відновлює перевірений runtime у власній папці залежностей. Native `canvas` у поточному старті не завантажується; дев’ять нових PNG/SVG/text-карток уже перевірено через чистий headless Chrome; native canvas та Telegram transport цим не сертифіковані.

## Що перевірено

- Source: усі 142 файли Work manifest збіглися; логіка бота збережена у 143-му санітизованому файлі. Вбудований webhook secret у копії замінено інертним значенням.
- Locked dependencies: 180 внутрішніх Replit tarball URL замінено на npm registry, версії/integrity залежностей збережені. Пізніше вже наявний Acorn8.15.0 оголошено прямою залежністю для статичного розбору джерела без виконання JS; версія й integrity не змінені.
- TypeScript, Vite/static build і окремі guard→legacy server bundles проходять.
- 17 перевірок ZIP intake, 7 негативних guard-тестів та 7 локальних інтеграційних smoke-перевірок проходять.
- Реальні pg/Drizzle user/settings/location routes читають і змінюють синтетичну БД; точний будинок `12А` відділений від `12`, інтервали містять `07:30` і `24:00`.
- Telegram/webhook/broadcast/OIDC/live adapters/legacy seed/reconciliation/schedulers вимкнені. Сторонній Origin/Host відхиляється. Перед імпортом старого сервера перевіряється конфігурація та встановлюється процесний guard. Це захист конкретних Node API, а не OS sandbox для довільного ворожого коду.
- Fresh headless Chrome: 390×844 та 1366×900, відновлення профілю, графік, налаштування; 0 page errors, зовнішніх запитів і popup. Скриншоти та докази — `../docs/light-bot-app/codex/`.

План/джерела передані з Work прийнято без повторного повного аудиту. Всі **68 must** залишаються у чинному реєстрі. `TECH-03` serving/source і live DB binding лишається pending; цей локальний результат його не доводить. Точний оригінальний запит відновлено. Погоджено спокійний світлий дизайн із зеленим акцентом та українську, ввічливе «ви», спокійно й без emoji. Actual картки й повні діалоги збережені в `../docs/light-bot-app/p2/`; фінальне приймання всього досвіду й пристроїв окреме. Дані ОСР і адресні прив'язки тут не сертифікувалися.

Поточні докази нової реалізації: `p2/product-smoke.json`, `p2/shared-profile/api-smoke.json`, `p2/store-smoke.json`, `p2/render-stress.json`, незалежні `p2/qa/`, репетиція й незалежне QA `p3/migration/`. Точний поточний стан і наступні дії — `../docs/light-bot-app/codex/PROGRESS_UA.md` і `checkpoint.json`.
