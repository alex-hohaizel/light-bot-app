## Як застосувати права у Codex

Не казати повторно «P0 доручення відсутнє»,коли прочитано цей запис із точною цитатою. Продовжити той самий read-only scope:прийняти докази,отримати/підготувати безпечну source-only копію,статику й необхідні metadata probes. Зберегти reports/стан у проєкті. Не повторювати вже виконане без source drift або конкретного залишкового питання.

Сама наявність наступної фази у PLAN не є дозволом на будь-який зовнішній effect. Для майбутнього коду/ізольованого запуску перевірити чинне застосовне доручення й startup consequences; для production writes/export/release/send потрібні конкретні targets/scope. Оборотні дії в межах фактичного доручення виконуються автономно; не додавати approval gate до кожного файлу.

Точні обрані бренд/палітра/тон не знайдені. У реєстрі вони mandatory pending decision з due,а не виключені або вигадані accepted choices.

## Пріоритет джерел

Прямі нові доручення власника й чинні рішення D-01–03 мають пріоритет над старими рекомендаціями БРИФу. Зокрема, рання пропозиція платного API скасована правилом API=0. Будь-яка деталізація критерію, запропонована асистентом, не створює нової волі власника. План стосується повного продукту; один technical slice не зменшує ціль.
